# IPv6 y protocolos auxiliares

IPv6 es la evolucion de IPv4 disenada para resolver el agotamiento de direcciones y mejorar las caracteristicas del protocolo. Con direcciones de 128 bits, IPv6 proporciona un espacio de direcciones tan vasto (3.4 x 10^38) que cada particula de la superficie terrestre podria tener multiples direcciones unicas.

Ademas de IPv6, la capa de red utiliza protocolos auxiliares como ARP, ICMP y DHCP que complementan el funcionamiento basico del enrutamiento IP.

## IPv6

### Direcciones de 128 bits

Una direccion IPv6 se representa en notacion hexadecimal con dos puntos, dividiendo los 128 bits en 8 bloques de 16 bits:

```
Ejemplo: 2001:0db8:85a3:0000:0000:8a2e:0370:7334

Reglas de simplificacion:
- Eliminar ceros iniciales en cada bloque: 2001:db8:85a3:0:0:8a2e:370:7334
- Un doble colon (::) reemplaza un o mas bloques consecutivos de ceros:
  2001:db8:85a3::8a2e:370:7334
- Solo se permite un :: en la direccion
```

### Tipos de direccion

**Unicast:**

- **Global Unicast (2000::/3):** direcciones enrutables en internet, equivalente a las direcciones IPv4 publicas.
- **Link-Local (fe80::/10):** direcciones automaticas generadas a partir de la direccion MAC. Solo son validas en el enlace local y no son enrutables.
- **Unique Local (fc00::/7):** equivalentes a las direcciones privadas IPv4, no enrutables en internet.
- **Loopback (::1):** equivalentes a 127.0.0.1 en IPv4.

**Multicast (ff00::/8):** direcciones para grupos de dispositivos. Reemplazan a los broadcast IPv4, reduciendo el trafico innecesario.

**Anycast:** una direccion asignada a multiples dispositivos; el paquete llega al mas cercano segun la metrica de enrutamiento.

### Ventajas sobre IPv4

- Espacio de direcciones practicamente infinito.
- Autoconfiguracion sin DHCP (SLAAC - *Stateless Address Autoconfiguration*).
- Cabecera simplificada (40 bytes fijos frente a 20-60 bytes variables en IPv4).
- IPSec integrado (opcion en IPv4, obligatorio en IPv6 originalmente).
- No necesita NAT (cada dispositivo puede tener direccion publica).
- Mejora en la eficiencia de enrutamiento con prefijos de enrutamiento jerarquicos.

## ARP (Address Resolution Protocol)

ARP resuelve direcciones IP a direcciones MAC en redes locales. Cuando un dispositivo quiere enviar un paquete a otra IP en la misma red, necesita conocer la MAC de destino. ARP envia una solicitud broadcast: "quien tiene la IP 192.168.1.5, dime tu MAC". El dispositivo con esa IP responde directamente con su MAC.

```
ARP Request (broadcast): "Who has 192.168.1.5? Tell 192.168.1.10"
ARP Reply (unicast): "192.168.1.5 is at 00:1A:2B:3C:4D:5E"
```

ARP se utiliza exclusivamente en redes locales. Los paquetes que deben atravesar un router utilizan ARP para llegar al router, y luego el router utiliza ARP para llegar al siguiente salto.

IPv6 no utiliza ARP; lo reemplaza con NDP (*Neighbor Discovery Protocol*), que combina ARP, ICMP Router Discovery y ICMP Redirect en un solo protocolo.

## ICMP (Internet Control Message Protocol)

ICMP proporciona mensajes de error y diagnostico para IPv4 e IPv6. No transporta datos de aplicaciones; su funcion es informar sobre problemas de red.

**Usos principales:**

- **ping:** envia una solicitud ICMP Echo y espera una respuesta ICMP Echo Reply. Mide la latencia y la conectividad.
- **traceroute:** envia paquetes con TTL incremental para descubrir los routers intermedios en el camino.
- **Mensajes de error:** Destination Unreachable (destino inalcanzable), Time Exceeded (TTL agotado), Redirect (redireccion a un router mejor).

```bash
# ICMP en accion
ping -c 4 8.8.8.8            # 4 solicitudes ICMP Echo
traceroute google.com         # Descubre routers intermedios
```

ICMP es utilizado tanto para diagnostico como por atacantes para sondear redes (*ping sweep*) y mapear topologia (*traceroute*), por lo que muchos firewalls bloquean ciertos tipos de mensajes ICMP.

## DHCP (Dynamic Host Configuration Protocol)

DHCP asigna direcciones IP y otra configuracion de red (mascara, gateway, DNS) a dispositivos automaticamente. Cuando un dispositivo se conecta a la red, envia una solicitud DHCP y un servidor DHCP le asigna una configuracion valida.

El proceso DHCP (*DORA*):

1. **Discover:** el cliente envia un broadcast buscando servidores DHCP.
2. **Offer:** el servidor responde con una oferta de direccion IP.
3. **Request:** el cliente acepta la oferta.
4. **Acknowledge:** el servidor confirma la asignacion.

```bash
# Renovar configuracion DHCP
sudo dhclient -r eth0    # Liberar
sudo dhclient eth0       # Solicitar nueva

# Ver configuracion actual
ip addr show eth0
```

> ARP, ICMP y DHCP son los pilares auxiliares de la capa de red. Sin ARP, los dispositivos no podrian comunicarse en la red local. Sin ICMP, no habria forma de diagnosticar problemas de conectividad. Sin DHCP, cada dispositivo tendria que configurarse manualmente, lo que seria impracticable en redes grandes.
