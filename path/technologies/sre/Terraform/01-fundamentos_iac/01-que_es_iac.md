# Que es Infraestructura como Codigo

La gestion de infraestructura ha sido tradicionalmente un proceso manual: un operador accedia a una consola web o ejecutaba comandos ad-hoc para aprovisionar servidores, configurar redes y ajustar balanceadores. Este modelo, ademas de ser propenso a errores humanos, generaba dependencia en el conocimiento tacito de individuos concretos. La Infraestructura como Codigo (IaC) invierte esta dinamica al tratar los componentes de infraestructura con el mismo rigor que el codigo fuente de una aplicacion: se definen en archivos de configuracion declarativos, se versionan en un sistema de control de versiones y se someten a procesos de revision y validacion automatizada.

En esencia, IaC consiste en describir el estado deseado de la infraestructura mediante archivos de configuracion legibles por maquina. Estos archivos se almacenan en repositorios Git, lo que proporciona un historial completo de cambios, la capacidad de revertir a estados anteriores y la trazabilidad de quien modifico que y cuando. Un recurso como una red virtual o una base de datos deja de ser un elemento efimero creado a traves de una interfaz grafica para convertirse en un bloque de codigo con version, autor y contexto.

El codigo de infraestructura es inherentemente reusable: un mismo conjunto de archivos puede desplegar entornos identicos en desarrollo, pruebas y produccion, eliminando la clasica discrepancia de "en mi maquina funciona". Tambien es consistente, ya que la ejecucion automatizada garantiza que el resultado final coincide exactamente con lo especificado, sin desviaciones introducidas por pasos manuales olvidados o interpretaciones subjetivas. Por ultimo, es auditable: cada cambio queda registrado, cada decision de diseno puede revisarse y cada despliegue puede repetirse de forma determinista.

## Enfoques Imperativo vs Declarativo

Dentro de IaC coexisten dos paradigmas fundamentales que determinan como se expresa la configuracion y como la herramienta actua sobre los recursos.

El enfoque **imperativo** se centra en el *como*: el usuario escribe una secuencia explicita de instrucciones que la herramienta debe ejecutar paso a paso para alcanzar el estado deseado. Es similar a una receta de cocina donde cada accion se detalla minuciosamente. Un ejemplo imperativo seria: "crear una VPC, luego crear una subred dentro de esa VPC, luego asociar una tabla de rutas a la subred". Herramientas como Ansible (en sus modulos mas procedurales) o scripts de shell con llamadas a la API cloud siguen este paradigma. La ventaja es el control granular sobre el orden y las condiciones de ejecucion. La desventaja es la fragilidad: si un paso falla a mitad del proceso, la infraestructura puede quedar en un estado inconsistente, y el script debe contemplar explícitamente cada error.

El enfoque **declarativo**, por el contrario, se centra en el *que*: el usuario especifica el estado final deseado y la herramienta determina automaticamente la secuencia de acciones necesaria para alcanzarlo. Siguiendo la analogia culinaria, seria equivalente a decir "quiero una tarta de manzana" sin especificar cada paso de la receta. Terraform es declarativo: se escribe un archivo de configuracion describiendo los recursos que deben existir (una VPC, una subred, una tabla de rutas) y Terraform calcula el plan de ejecucion, detecta el orden optimo basandose en dependencias y aplica los cambios respetando el grafo de recursos.

La principal fortaleza del enfoque declarativo es la idempotencia: ejecutar la misma configuracion mil veces produce exactamente el mismo resultado, y si la infraestructura ya se encuentra en el estado deseado, no se realiza ninguna accion. Esto simplifica drasticamente la gestion de cambios y la recuperacion ante fallos, ya que la herramienta converge al estado deseado desde cualquier punto de partida. Terraform, al ser declarativo, abstrae al operador de los detalles de ordenacion y gestion de errores, delegando esa responsabilidad al motor interno que calcula el grafo de dependencias y genera el plan de ejecucion.

> La distincion entre imperativo y declarativo no es absoluta: herramientas declarativas como Terraform permiten ciertos mecanismos imperativos (como `local-exec` o `remote-exec`) para casos excepcionales, aunque las buenas practicas recomiendan minimizar su uso.
