# Generadores de identidad

La generacion de identificadores unicos es uno de los aspectos fundamentales del mapeo objeto-relacional. JPA define varias estrategias estandar a traves de `@GeneratedValue`, y Hibernate las amplia con generadores adicionales y la posibilidad de crear generadores personalizados mediante `@GenericGenerator`.

## IDENTITY

La estrategia `IDENTITY` delega en la base de datos la generacion del identificador, tipicamente mediante una columna auto-incremental (MySQL, SQL Server, H2) o una secuencia nativa configurada como generador identidad (PostgreSQL con `GENERATED BY DEFAULT AS IDENTITY`).

```java
@Entity
@Table(name = "usuarios")
public class Usuario {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
}
```

La principal limitacion de `IDENTITY` es que impide el uso de ciertas optimizaciones de Hibernate. Dado que el identificador se genera en la base de datos durante el INSERT, Hibernate no conoce el ID antes de ejecutar la sentencia. Esto impide el batching de inserciones (`jdbc.batch_size`) porque cada INSERT debe ejecutarse inmediatamente para obtener el ID generado, salvo que se active `reWriteBatchedInserts`.

## SEQUENCE

La estrategia `SEQUENCE` utiliza una secuencia de base de datos para obtener el siguiente valor del identificador. Es la opcion preferida para la mayoria de los proyectos porque no bloquea el batching y ofrece el mejor rendimiento.

```java
@Entity
@Table(name = "usuarios")
public class Usuario {

    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "seq_usuarios")
    @SequenceGenerator(name = "seq_usuarios", sequenceName = "usuarios_seq",
                       allocationSize = 50)
    private Long id;
}
```

El parametro `allocationSize` controla cuantos IDs se reservan en cada llamada a la secuencia. Un valor de 50 significa que Hibernate obtiene 50 IDs de una sola vez y los distribuye entre las nuevas entidades, reduciendo las idas y vueltas a la base de datos.

> Desde Hibernate 5, la estrategia por defecto es `SEQUENCE` (aunque antes era `AUTO`) y Hibernate utiliza internamente `SequenceStyleGenerator` que elige automaticamente entre secuencia o tabla segun el soporte de la base de datos.

## TABLE

La estrategia `TABLE` simula una secuencia utilizando una tabla de base de datos que almacena el ultimo valor asignado. Es portable entre todos los motores de base de datos, pero tiene un rendimiento significativamente inferior al de `SEQUENCE`.

```java
@Entity
@Table(name = "usuarios")
public class Usuario {

    @Id
    @GeneratedValue(strategy = GenerationType.TABLE, generator = "tabla_ids")
    @TableGenerator(name = "tabla_ids", table = "secuencias",
                    pkColumnName = "nombre_seq", valueColumnName = "valor_seq",
                    pkColumnValue = "seq_usuarios", allocationSize = 50)
    private Long id;
}
```

> El uso de `TABLE` solo se justifica cuando se necesita portabilidad absoluta entre bases de datos que no soportan secuencias. En cualquier otro caso, `SEQUENCE` es preferible. El acceso a la tabla `secuencias` requiere bloqueos de fila que pueden convertirse en un cuello de botella.

## AUTO

La estrategia `AUTO` delega en Hibernate la eleccion de la estrategia mas adecuada segun el dialecto configurado. En Hibernate 5 y versiones posteriores, `AUTO` se resuelve como `SEQUENCE` para bases de datos que soportan secuencias.

```java
@Entity
public class Usuario {

    @Id
    @GeneratedValue(strategy = GenerationType.AUTO)
    private Long id;
}
```

> Aunque `AUTO` parece comodo, es recomendable especificar explicitamente la estrategia para evitar sorpresas al migrar entre bases de datos o versiones de Hibernate.

## UUID

Hibernate proporciona generadores nativos para identificadores UUID. La estrategia `uuid2` genera identificadores unicos universales en formato String estandar (8-4-4-4-12).

```java
@Entity
public class Pedido {

    @Id
    @GeneratedValue(generator = "uuid")
    @GenericGenerator(name = "uuid", strategy = "uuid2")
    private String id;
}
```

Los UUIDs son utiles en sistemas distribuidos donde multiples nodos deben generar identificadores sin coordinacion. Sin embargo, ocupan mas espacio que los numeros (36 caracteres vs 8 bytes de un Long) y las inserciones en indices agrupados pueden ser menos eficientes debido a la aleatoriedad del valor.

## Hi-Lo algorithm

El algoritmo Hi-Lo es una tecnica de generacion de IDs que minimiza las llamadas a la base de datos. Funciona con dos valores: un valor "hi" (alto) que se obtiene de la base de datos y un valor "lo" (bajo) que se incrementa localmente. El ID se calcula como `(hi - 1) * maxLo + lo`.

```java
@Entity
public class Usuario {

    @Id
    @GeneratedValue(generator = "hilo")
    @GenericGenerator(name = "hilo", strategy = "org.hibernate.id.enhanced.SequenceStyleGenerator",
        parameters = {
            @Parameter(name = "sequence_name", value = "hilo_seq"),
            @Parameter(name = "initial_value", value = "1"),
            @Parameter(name = "increment_size", value = "100"),
            @Parameter(name = "optimizer", value = "pooled-lo")
        })
    private Long id;
}
```

El optimizador `pooled-lo` es la variante moderna del Hi-Lo clasico. Reserva un bloque de IDs (por ejemplo, 100) en cada llamada a la secuencia, de modo que la aplicacion puede asignar hasta 100 IDs sin volver a consultar la base de datos. Cuando se agota el bloque, se obtiene el siguiente.

> `pooled-lo` es el optimizador por defecto de `SequenceStyleGenerator` con `allocationSize > 1`. No confunde con `pooled` (sin el sufijo `lo`), que tiene un comportamiento ligeramente distinto en la forma de combinar los valores hi y lo.

## Generadores personalizados

Cuando las estrategias predefinidas no cubren la necesidad, se puede implementar un generador personalizado extendiendo `AbstractIdGenerator` o implementando `IdentifierGenerator`:

```java
public class PrefijoGenerador implements IdentifierGenerator {

    @Override
    public Object generate(SharedSessionContractImplementor session, Object object) {
        // Logica personalizada: prefijo + timestamp + contador
        return "PROD-" + System.currentTimeMillis() + "-"
            + ThreadLocalRandom.current().nextInt(1000, 9999);
    }
}

@Entity
public class Producto {

    @Id
    @GeneratedValue(generator = "prefijo")
    @GenericGenerator(name = "prefijo", strategy = "com.ejemplo.PrefijoGenerador")
    private String codigo;
}
```

> Los generadores personalizados deben ser cuidadosamente diseñados para garantizar la unicidad del identificador, especialmente en entornos clusterizados o con alta concurrencia. Depender de `System.currentTimeMillis()` sin sincronizacion puede producir duplicados si dos generadores se ejecutan en el mismo milisegundo.
