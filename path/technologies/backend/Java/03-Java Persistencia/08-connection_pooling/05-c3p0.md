# C3P0

C3P0 es una libreria de pool de conexiones JDBC con una larga trayectoria en el ecosistema Java. Fue uno de los primeros pools ampliamente adoptados, pero su rendimiento y diseno han quedado desfasados frente a alternativas modernas como HikariCP. Actualmente su uso se limita casi exclusivamente a proyectos legacy que no han migrado a pools mas eficientes.

## ComboPooledDataSource

La clase principal de C3P0 es `ComboPooledDataSource`, que implementa `javax.sql.DataSource` y proporciona la funcionalidad completa del pool.

```java
ComboPooledDataSource ds = new ComboPooledDataSource();
ds.setJdbcUrl("jdbc:postgresql://localhost:5432/mibd");
ds.setUser("usuario");
ds.setPassword("contrasena");
ds.setDriverClass("org.postgresql.Driver");

ds.setInitialPoolSize(5);
ds.setMinPoolSize(5);
ds.setMaxPoolSize(20);
ds.setAcquireIncrement(3);
ds.setMaxIdleTime(600);
ds.setMaxConnectionAge(1800);
ds.setCheckoutTimeout(30000);
ds.setIdleConnectionTestPeriod(60);
ds.setTestConnectionOnCheckout(true);
ds.setPreferredTestQuery("SELECT 1");
```

## Configuracion en Spring Boot

Para usar C3P0 con Spring Boot es necesario anadir la dependencia y configurar el tipo de DataSource:

```xml
<dependency>
    <groupId>com.mchange</groupId>
    <artifactId>c3p0</artifactId>
    <version>0.9.5.5</version>
</dependency>
```

```properties
spring.datasource.type=com.mchange.v2.c3p0.ComboPooledDataSource
spring.datasource.c3p0.initial-pool-size=5
spring.datasource.c3p0.min-pool-size=5
spring.datasource.c3p0.max-pool-size=20
spring.datasource.c3p0.acquire-increment=3
spring.datasource.c3p0.max-idle-time=600
spring.datasource.c3p0.max-connection-age=1800
spring.datasource.c3p0.checkout-timeout=30000
spring.datasource.c3p0.idle-connection-test-period=60
spring.datasource.c3p0.test-connection-on-checkout=true
spring.datasource.c3p0.preferred-test-query=SELECT 1
```

## Rendimiento

C3P0 es el mas lento de los pools de conexiones utilizados comunmente en Java. Su diseno original priorizaba la estabilidad y la compatibilidad sobre el rendimiento.

```text
Tiempo medio por operacion getConnection/close:

HikariCP  : 0.05 ms
DBCP2     : 0.35 ms
C3P0      : 0.80 ms
```

Las causas principales de su bajo rendimiento son:
- Sincronizacion exhaustiva en todos los metodos del pool, lo que genera contenucion de hilos.
- Procesos de limpieza y validacion internos que se ejecutan con demasiada frecuencia.
- Gestion ineficiente de la memoria, con multiples objetos creados por conexion gestionada.
- Implementacion del registro de eventos que bloquea durante la escritura.

## Problemas conocidos

C3P0 tiene varios problemas documentados que han motivado su abandono en proyectos modernos:

- **Fugas de hilos**: en condiciones de alta concurrencia, los hilos internos de limpieza pueden quedar bloqueados, causando que el pool deje de responder.
- **Consumo excesivo de memoria**: cada conexion gestionada mantiene multiples objetos auxiliares que no se liberan correctamente.
- **Inestabilidad bajo carga**: el pool puede entrar en un estado inconsistente cuando se supera el maximo de conexiones simultaneas.
- **Fallo en la reconexion**: tras una perdida de conexion con la base de datos, C3P0 no siempre logra restablecer el pool correctamente.

```text
Error tipico en logs de aplicaciones con C3P0:

WARN  - com.mchange.v2.resourcepool.BasicResourcePool -
  com.mchange.v2.resourcepool.BasicResourcePool$ScatteredAcquireTask@1234
  -- Acquisition Attempt Failed!!! Clearing pending acquires.
```

## Cuando tiene sentido usar C3P0

El unico escenario donde tiene sentido mantener C3P0 es en proyectos legacy donde el cambio de libreria implicaria un esfuerzo de migracion desproporcionado. En estos casos, la configuracion debe ser conservadora para minimizar los problemas conocidos.

```properties
# Configuracion conservadora para proyectos legacy con C3P0
spring.datasource.c3p0.initial-pool-size=3
spring.datasource.c3p0.min-pool-size=3
spring.datasource.c3p0.max-pool-size=10
spring.datasource.c3p0.acquire-increment=1
spring.datasource.c3p0.max-idle-time=300
spring.datasource.c3p0.max-connection-age=600
spring.datasource.c3p0.checkout-timeout=15000
spring.datasource.c3p0.idle-connection-test-period=30
spring.datasource.c3p0.test-connection-on-checkout=false
spring.datasource.c3p0.test-connection-on-checkin=true
```

> Para proyectos nuevos, la unica recomendacion sensata es usar HikariCP. C3P0 no recibe mejoras de rendimiento significativas y su arquitectura esta obsoleta. Mantenerlo en un proyecto nuevo es anadir deuda tecnica sin justificacion.

## Migracion desde C3P0

La migracion desde C3P0 a HikariCP es relativamente sencilla. Los cambios principales son:
1. Reemplazar la dependencia de `c3p0` por `HikariCP` (ya incluida en Spring Boot).
2. Cambiar `spring.datasource.type` o eliminar la configuracion especifica de C3P0.
3. Renombrar las propiedades segun la nomenclatura de HikariCP.
4. Verificar que el comportamiento transaccional y de validacion se mantiene.

```properties
# Antes (C3P0)
spring.datasource.c3p0.max-pool-size=20
spring.datasource.c3p0.min-pool-size=5
spring.datasource.c3p0.checkout-timeout=30000

# Despues (HikariCP)
spring.datasource.hikari.maximum-pool-size=20
spring.datasource.hikari.minimum-idle=5
spring.datasource.hikari.connection-timeout=30000
```

La migracion no solo mejora el rendimiento, sino que elimina los problemas de estabilidad asociados a C3P0 y reduce el consumo de memoria de la aplicacion.
