# Que es persistencia

Todo sistema de software, en su funcionamiento, genera y manipula datos que deben sobrevivir al ciclo de vida del proceso que los creo. Un programa que se ejecuta, carga informacion en memoria RAM y opera sobre ella; en cuanto la aplicacion termina, el espacio de memoria se libera y los datos desaparecen. La persistencia es el mecanismo por el cual esos datos se almacenan de forma duradera en un medio no volatil, de manera que puedan ser recuperados en una sesion posterior, por el mismo proceso o por otro distinto.

La memoria volatil (RAM) ofrece velocidad y acceso directo, pero es costosa, limitada en capacidad y, sobre todo, efimera. Los medios de persistencia --discos duros, unidades de estado solido, memorias NAND, cintas magneticas-- proporcionan almacenamiento masivo a un costo mucho menor por unidad de informacion, aunque con latencias de acceso varios ordenes de magnitud superiores. Esta diferencia fundamental determina la arquitectura de cualquier sistema que maneje datos: los datos calientes (hot data) residen en memoria cache o RAM para acceso rapido, mientras que los datos frios (cold data) se mantienen en almacenamiento persistente.

Los medios fisicos donde se materializa la persistencia son variados. El mas tradicional es el archivo plano (fichero de texto o binario) en el sistema de archivos del sistema operativo. Las bases de datos relacionales (PostgreSQL, MySQL, Oracle) anaden estructura, indexacion, integridad referencial y un lenguaje de consulta declarativo (SQL). Las bases de datos NoSQL (MongoDB, Redis, Cassandra) sacrifican consistencia fuerte o esquemas estrictos a cambio de escalabilidad horizontal o latencias reducidas. Las caches (Redis, Memcached) actuan como capas intermedias de persistencia volatil con respaldo en disco.

Persistir datos responde a necesidades concretas. La recuperacion ante fallos exige que el estado de una aplicacion pueda reconstruirse tras un cierre inesperado o una caida del sistema. La comparticion entre multiples instancias de una aplicacion --o entre distintas aplicaciones-- requiere un repositorio comun accesible desde distintos procesos, maquinas o incluso centros de datos. La auditoria y el cumplimiento normativo obligan a conservar trazas de operaciones durante anos, con garantias de inmutabilidad y trazabilidad. Sin persistencia, cualquier sistema seria una maquina de estados sin memoria, incapaz de acumular conocimiento, historial o configuracion.

En la arquitectura de software, la capa de persistencia es el componente encargado de aislar la logica de negocio de los detalles concretos de almacenamiento. Esta abstraccion permite cambiar el motor de base de datos, el esquema de tablas o incluso el paradigma de almacenamiento sin modificar el codigo de la capa de negocio. En Java, esta capa se materializa a traves de tecnologias como JDBC, JPA, Hibernate o Spring Data, cada una con distintos niveles de abstraccion y control.
